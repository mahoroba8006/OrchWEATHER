# アプリ本体ビジュアル全面リニューアル「空が主役」設計書（2026-09-30）

## 目的

機能・情報・操作仕様を一切変えずに、アプリ本体（空もよう／空くらべ／空しらべ／設定／ヘルプ／ログイン）の画面デザインを全面刷新する。
「いかにもAIが作ったデザイン」から脱し、開く・選ぶこと自体が楽しいプロダクト品質のUIにする。

### 現状の「AI感」の原因（是正対象）

1. ティール→ブルーのグラデーション、ガラスモーフィズム、ティール色の影
2. Outfit/Inter＋lucide既定のまま。日本語書体設計がない
3. 全カードが同じ角丸・同じ影・同じ重みで並び、情報の主従がない
4. インラインstyle約550箇所に色が直書き（配色変更時に「緑が残る」問題の根本原因）

### 対象外

- LP（2026-07-21刷新済み）。最終段階で統一感の調整のみ行う
- 機能追加・データ仕様・API・ジェスチャーのロジック（`src/lib/chartViewport.ts` 等）

## 合意済みの方針

| 論点 | 決定 |
|---|---|
| デザイン方向性 | A: 空が主役（ダイナミックスカイ） |
| 空の範囲 | ヒーロー型（上部のみ空。データ面は常に明るい） |
| モーション実装 | Motion ライブラリ導入（`motion`、LazyMotion＋`m` で軽量化） |
| 設定画面の区別 | 下から出るシート（色による区別は撤去） |

## 1. デザインシステム

### 配色トークン

- **面（不透明3段）**: 地 `#F4F3EF` ／ カード `#FFFFFF` ／ くぼみ `#ECEAE4`
- **文字（3段）**: 主 `#17191C` ／ 副・補助はこれの濃度違い（コントラスト比4.5以上を保証）
- **アクセント（1色のみ）**: `#0E6B65`（フラット。グラデーション禁止）
- **意味色**: 気温（寒→暖スケール）・降水（青）・警報/注意報（既存の意味色）はデータ表現にのみ使用
- **影**: 無彩色のごく淡い1種のみ。境界は細い線（墨色の低透明度）
- **撤去**: `glass-panel`/`glass-card` の半透明＋blur、ボタンのグラデーション、色付き影、`--settings-*` インディゴ系トークンと `.settings-theme`

### 空パレット（ヒーロー専用）

- 時間帯6種: 夜明け／朝／昼／夕焼け／薄暮／夜。判定は `DailyForecastData.sunrise` / `sunset`（既存データ）と現在時刻から算出
- 天気6種: 晴れ／くもり／雨／雪／雷／霧。現在時刻の時間別予報の天気コードから分類
- 時間帯×天気でグラデーションを生成。くもり・雨は彩度を落とす
- 空の上の文字は白。全パレットでコントラスト比4.5以上を満たすこと（満たせない組み合わせは空側を暗くして調整）

### 書体

- **IBM Plex Sans JP に統一**（Google Fonts、unicode-range 分割で必要字形のみ取得）
- 数値は等幅数字（`font-variant-numeric: tabular-nums`）
- ヒーロー気温のみ Light（300）で特大表示
- Outfit / Inter は撤去

### 形

- 角丸: カード16px、ボタン・タブ・チップは完全な丸（999px）
- 余白: 4pxグリッド
- UIアイコン: lucide 継続、`strokeWidth` 1.5 に統一
- 天気アイコン: Meteocons **v2形式のみ**（v3形式はモバイルの img 文脈で描画失敗するため不可）

### モーション原則

ばね3種を定義し全画面で使い回す（値は実装時に実機で微調整）:

| 名前 | 用途 | 初期値の目安 |
|---|---|---|
| press | 押下の沈み込み・戻り | stiffness 600 / damping 30 |
| move | 選択印の移動・レイアウト変化・シート | stiffness 380 / damping 34 |
| enter | 登場・フェードアップ | stiffness 180 / damping 26 |

- 動かすのは `transform` と `opacity` のみ（低性能Androidで60fps維持）
- `prefers-reduced-motion: reduce` では全モーションを即時切り替えに置換（Motion の `MotionConfig reducedMotion="user"`）

### 実装の土台

- トークンは `src/index.css` の CSS変数に一元化。ばね定義は `src/lib/motion.ts` に一元化
- 共通部品を新設: ボタン、スライドするタブ／セグメント、シート、トグル、骨組み表示（スケルトン）
- インラインstyleの色直書きは、各画面の刷新時に段階的にトークンへ置換する

## 2. アプリの骨格

### ヒーロー（空もよう）

- 初期表示で画面上部の約45%を空が占有
- 表示内容: 地点名（タップで地点切替）／今の気温（特大細字）／天気の文字表記／今日の最高・最低／天気アイコン
- 空の演出: グラデーションがゆっくり呼吸。天気に応じて粒子を重ねる（雲が流れる・雨粒・雪・霧のたなびき・稀な雷光）
  - SVG＋CSSで描画、画像不使用
  - 粒子は同時最大60個
  - ヒーローが画面外に出たとき、およびページが非表示（`visibilitychange`）のときは描画停止
- スクロールで空が縮み、高さ56pxのヘッダーになる。気温表示は同一要素のまま大→小へ移動
- 起動後の初回のみ: 気温のカウントアップ＋下のカードが順に浮かび上がる。タブ往復では再生しない

### 空くらべ・空しらべ

- 大きなヒーローは置かない（現在天気の情報がないため）
- 同じ空の色を帯状に敷いた低いヘッダー（約72px）に画面タイトルを表示

### ナビゲーション

- **ボトムナビ（モバイル）**: 白い面にアイコン＋文字。選択中は背後の丸いハイライトが滑って移動（Motion `layoutId`）。押下で沈み、離すと弾む
- **PCヘッダー**: 同構造の横並び。選択ハイライトが滑る点も同じ
- **タブ切り替え**: ナビの並び順と連動した方向に横スライド

### 設定・ヘルプ（シート化）

- ヘッダー右上のアイコンから開く
- モバイル: 元画面が94%に縮んで暗転し、シートが下からばねでせり上がる。下スワイプまたは×で閉じる
- PC: 右から出る幅480pxのパネル
- シート内から地図モーダル（地点選択）を開く場合の二重の重なりは、z-index と暗転の段階を設計して破綻させない
- 既存の `topTab` の `'settings' | 'help'` 状態は「シート開閉状態」へ置き換える。戻り先管理（`prevTopTab`）は不要になる

### ログイン画面

- 夜明けの空をフルスクリーンで表示

## 3. 各画面の中身（見せ方のみ変更）

### 空もよう

- **注意報**: 発表中のみヒーロー直下に帯で表示。登場時に帯が左→右へ一度伸びる。警報は控えめな脈動を3回のみ
- **日別予報**: 各日を縦長カードで横並び。最高・最低気温は「期間全体の気温幅に対する位置」を示す横線で表現。注意報ガントバー・天気コードモード切替・ミニアイコン等の既存機能は全て維持。日をタップで選択印が滑り、時間別予報がその日へ滑らかにスクロール
- **時間別予報**: 行罫線を廃し細い区切り＋等幅数字。現在時刻の列に縦ハイライトを常時表示。降水量は数字に加え薄青の棒を下に敷く
- **AIコメント**: 生成待ちは空モチーフの専用ローディング（雲が集まって文章になる）。本文は一行ずつふわりと表示。セクション切替のスワイプは指に追従し、離すとばねで止まる

### 空くらべ・空しらべ

- チャートの線は細く、色は意味色のみ。グリッドは極めて淡く
- タップ時の十字線・値表示は Motion で滑らかに追従
- ピンチ・スワイプ・Ctrl＋ホイールのジェスチャーロジックには**手を入れない**（見た目のみ）
- 表示単位・期間選択はハイライトが滑るセグメントに統一
- 表の見出しは固定、数字は等幅、1行おきに淡い色

### 設定（シート内）

- サブタブは下線が滑るタブ
- 保存ボタン: 押下でボタン内にチェックが描かれ「保存しました」に変化。Firestore 書き込みの await＋try/catch＋UIフィードバックは既存のまま維持
- 地点リストの追加・削除・並べ替えで行が滑らかに詰まる

### 共通の小さな動き

- 読み込み中: 回転アイコンを廃し、表の形の骨組み表示を淡く光らせる
- エラー: 横に軽く揺れてから表示
- トグル: つまみにばねの動き

## 4. 進め方・品質保証・リスク

### 段階（各段階で develop へ出し、ユーザー実機確認）

1. **土台**: トークン・書体・Motion 導入とばね定義・共通部品・Playwright 導入。画面は色と書体が変わる程度
2. **骨格**: ヒーロー空＋粒子・スクロール縮小・ナビ・タブ切替・設定/ヘルプのシート化
3. **空もよう**: 注意報・日別・時間別・AIコメント
4. **空くらべ・空しらべ**: チャートと表（着手前に空くらべ画面を App.tsx から別ファイルへ純粋移動で切り出す）
5. **設定の中身・ログイン・LPとの統一調整**

main への反映は毎回ユーザーの明示指示を待つ。

### 作業環境

- worktree `feature/app-redesign` で作業し、段階ごとに develop へ取り込む

### 品質基準

- **機能不変**: 既存テスト44件全通過、`npm run build` 通過、段階ごとの操作確認リスト（地点切替・スワイプ・ピンチ・ズーム・保存・ログイン・ゲスト表示・注意報表示・AIコメント）を実画面で確認
- **見た目の検証**: Playwright（開発依存）で主要画面を 375px／1280px で自動撮影し、AI側で目視確認してからユーザー実機確認へ回す
- **性能予算**: 転送量の増加は圧縮後合計50KB以内（フォントは unicode-range 分割分を除く）。粒子最大60個。非表示時は描画停止
- **アクセシビリティ**: コントラスト比4.5以上（空上の白文字含む）、reduced-motion 対応、キーボードフォーカス表示

### リスクと対策

| リスク | 対策 |
|---|---|
| App.tsx 2,780行に空くらべ画面が直書きで巻き込み事故が起きやすい | 段階4の前に純粋移動で別ファイル化し、テストで挙動同一を確認。今回の改修に必要な範囲に限定 |
| AI側でスクリーンショットを確認できない | 段階1で Playwright を導入し自動撮影 |
| 空パレットの一部組み合わせで白文字のコントラスト不足 | パレット定義時に全36組み合わせのコントラスト比をテストで検証 |
| 粒子演出による低性能端末での発熱・電池消費 | 粒子上限・非表示時停止・reduced-motion 時は静止画 |
| 設定シート化で既存の設定画面の状態管理が変わる | `topTab` からの分離は段階2で単独コミットにし、設定の保存・地図モーダルを重点確認 |

### 実装分担

- 実装はサブエージェントに委任。デザイン判断・レビュー・スクリーンショット検証は本セッション側が行い、品質の最終責任を持つ
