# LP ゼロベース作り直し仕様書：「一日×一年の空」

作成日: 2026-10-06 ／ 状態: 承認済み（2026-10-06）
前版: [2026-10-05-lp-renewal-design.md](2026-10-05-lp-renewal-design.md)（見出し・文言の制約・詳しく読む層の中身を引き継ぐ）

## 目的

LP を見た瞬間にアプリの姿と魅力が伝わり、プロが作り込んだ印象を与えるものにする。基調は青空と緑で、爽やかで洗練された印象にする。「AI が作った」雰囲気は徹底的に排除する。

## 中心のメッセージ

- 見出し: **「今年は遅い」が、数字で見える。**
- 添える言葉: **勘を、数字で裏づける。**
- このアプリならではの魅力: 農家が肌で感じる「今年は遅い」「雨が多い」を、去年・5年平均との実績比較で裏づけられること。これに、二十四節気の暦の美しさと、農家が自分のために作ったという出自が加わる。

## 体験の骨格：スクロール＝一日×一年

背景は画面の奥に固定した空が1枚だけで、全章で共通。スクロールの進み具合（0→1）に応じて、時刻と季節が同時に進む。

| 進み具合 | 空（時刻） | 季節 | 丘の色 | 舞うもの・空の要素 |
|---|---|---|---|---|
| 0〜0.25 | 夜明け→朝 | 春（立春〜穀雨） | 若草 | 桜の花びら |
| 0.25〜0.5 | 昼 | 夏（立夏〜大暑） | 濃い緑 | 光の粒・入道雲・強い日差し |
| 0.5〜0.75 | 夕焼け | 秋（立秋〜霜降） | 黄金色・紅葉 | 落ち葉 |
| 0.75〜1 | 夜 | 冬（立冬〜大寒） | 雪の白 | 雪・星・月 |

- 太陽は左から昇って右へ沈み、夜には月と星が出る（試作 `day-season-v2` で確認済み）。
- 節気は進み具合 × 24 で決め、季節の区切りと一致させる（試作で、昼＝芒種、夕焼け＝白露になることを確認済み）。
- 上部の帯に、ロゴ・「05:30 立春」のような時刻と節気・ログインを常に出す。PC では右端に二十四節気の目盛りを置く。
- 舞うものは**少なく、ゆっくり**（試作 v2 の設定: 26個・落下速度と揺れ約1/3）。画面外では描画を止める。
- 丘は稜線を複数重ね、田の畦や遠くの山並みを描き込んで奥行きを出す（写真は使わない）。

## 章の構成（スマホ 375px を基準に作り、PC は横に広げる）

### 0. 最初の画面（夜明け・立春）
- 上から順に: 今日の節気の札 → 見出し → 添える言葉 → 用途の一文 → ボタン2つ（「ログインせずに試す」「Googleで始める」を同じ強さで） → ボタンの下の一行。
- 今日の節気の札: 見た日の二十四節気・七十二候をその場で計算して、見出しの上に小さく出す（`sekki.ts`。通信なし）。見出しの下に置かないのは、一文を足しても縦に積む段数を増やさないため。
- 用途の一文: **「あなたの農園の天気が見える。あの年・あの場所との違いが見える。」**（2026-10-06 ユーザー指示で変更）（見出しだけでは何ができるか伝わらないため。表示中の東京の数字を「自分の地域でも見られる」と結びつける）
- ボタンの下の一行: **「Googleアカウントですぐにログイン。無料で利用できます」**
- 札「積算温度 去年より18日遅い」の下に、撮影時点 **「東京・2026年10月5日時点」** を小さく添える（撮影時点の数字を今日の実績と誤解させない）。
- 演出: 見出しが一行ずつ下からせり上がる／丘の向こうからアプリ画面（ふりかえりカード）が昇る／札の数字が 0→18 と数え上がる／雲が手前と奥で違う速さで流れる。

### 1. 勘の章（朝・春）＝最大の見せ場
- 画面を止めたまま（sticky）、スクロール3回分で3つの勘を順に見せる。
  1. 「今年は、遅い気がする。」→ 積算温度 去年より18日遅い（5年平均より12日遅い）
  2. 「雨、多すぎないか。」→ 白露の雨 5年平均の5.9倍
  3. 「お日さま、足りてない。」→ 日照 5年平均より64時間少ない
- 最後に大きく「勘を、数字で裏づける。」。その下に、3つの比較結果を落ち着いた文字で一行ずつ残す（演出の記憶と中身の理解を両方残す。画面写真で共有されても価値が伝わる）。
  - 積算温度：去年より18日遅い
  - 白露の雨：5年平均の5.9倍
  - 白露の日照：5年平均より64時間少ない
- 小さく「東京・2026年の実績」と添える。
- 動きを減らす設定では、3つの勘と数字をすでに縦に並べているので、結論の下の3行は出さない。
- 演出: 言葉が一文字ずつ溶けて消え、数字が数え上がる。進み具合の目盛りを出す。タイプライター風の演出は使わない。

### 2. 節気のふりかえり（昼前・初夏）
- 見出し「二十四節気ごとに、今年の半月を一枚に。」／縦書き「暦は、農の時計だった。」
- 縦スクロールに合わせて、節気の水彩画24枚（`SekkiArt`）が横へ流れる。白露で止まり、本物のふりかえりカードの画面が下からせり上がる。
- カードの下に、季節のあしどりの帯の画面を添える（毎日トップに一行で出ることを示す）。

### 3. 空くらべ（昼・夏）
- 見出し「去年と、あの場所と、並べて見える。」
- LP 上で描く積算温度のグラフ（実際の値の形）。スクロールに合わせて今年と去年の線が伸び、二本の間に「18日」の差が横棒で現れる。
- 3つの要点（年をまたいで比べる／地点を並べて比べる／積算温度を自動で）が順に灯る。続けて本物の画面2枚（年比較の気温・積算温度）。

### 4. 空もよう（午後・晩夏）
- 見出し「今日の作業、やるかやめるかすぐ決まる。」
- 「リスクでみる／概況でみる」は押せるボタンにし、押すと写真と説明が一緒に切り替わる（**写真は新しく2枚撮影**）。説明は「リスクでみる：その時間帯の、いちばん悪い天気」「概況でみる：その時間帯の、いちばん多い天気」。
  - 最初は「リスクでみる」。押されるまでは、画面に見えている間だけ自動で切り替える（触らない人にも違いが伝わる）。一度押したら自動切替は止める。画面外ではタイマーを止める。
  - 「タップで切り替え」と小さく添え、押せるのは切り替えボタンだけだと分かるようにする。
  - 押されている状態は `aria-pressed` で伝える。説明の読み上げは押した後だけ（自動切替の間は読み上げない）。
- 「ぽつぽつ」「カッパ？」「カッパ！」の札が、雨粒のように画面の脇へ落ちてくる。

### 5. 作った人＋詳しく読む（夕焼け・秋）
- 明朝の一行「現場で欲しかったものを、自分で作った。」＋短い本文（現行の文章を引き継ぐ）。
- 詳しく読む層: 生成り色の紙の帯を開くと中身が出る。中身は現行の文章をそのまま使う（機能をくわしく／一般の天気アプリとの違い・料金（有料は※予定）／よくある質問）。開閉は GA4 `lp_detail_open` で計測する（継続）。

### 6. 最後のボタン＋フッター（夜・冬）
- 「今日は〇〇。」（その日の節気）＋「今年の季節を、数字で見てみる。」＋ボタン2つ。
- フッターは現行の文章（ご利用上の注意・規約類のリンク・データ提供元）を引き継ぎ、雪の丘の下に置く。

## 見た目の方針

- 書体: 見出しは Shippori Mincho（800、`palt`）。本文は Zen Kaku Gothic New。時刻・数字の小さな札は DM Mono。大きな数字は等幅の数字で揃える。
- 色: 空と丘の色はキーフレームで補間する（試作 v2 の値を出発点とする）。文字は白で、薄い影を付ける。紙の帯は生成り色、文字は深い青緑（#16303A）。
- 避けるもの: オーロラ風のグラデーション、紫系の色、ガラス風カード、絵文字やアイコンの飾り、全要素に同じフェードを付けること、同じ高さの章の繰り返し、真ん中寄せの見出しに3枚のカードを並べる構成。
- 動きの緩急: 長くゆっくりした動きを少数にする。動きごとにイージングと長さを変える。

## 作り方

- 現行アプリの中で作り直す。`LandingPage.tsx` は組み立てだけにし、章ごとの部品を `src/components/lp/` に分ける。
- 背景の空・丘・舞うもの・太陽と月・星は、1つの部品（`<canvas>`＋SVG）にまとめる。スクロールの進み具合は、rAF でまとめた自前のフック（現行 LP で実績のある方式）で取る。`motion` は動きを減らす設定の判定（`useReducedMotion`）に使う。
- 新しいライブラリは入れない（GSAP・Lenis などは使わない）。
- LP は `React.lazy` で遅延読み込みにする（現行は `App.tsx` が直接 import している）。アプリ本体の読み込みを重くしない。
- 引き継ぐもの: ログイン処理（ポップアップ／iOS ホーム画面ではリダイレクト）、`onTryGuest`、GA4 の計測、Nav のログイン。
- 書体は Google Fonts から読み込む。CSP（`public/_headers`）は fonts.googleapis.com と fonts.gstatic.com を許可済み（確認済み）。

## 動きを減らす設定（prefers-reduced-motion）

- 空は章ごとの色に静かに切り替える。舞うものは出さない。
- 文字はすぐ表示し、数字は最終の値で出す。
- 画面を止めて見せる演出（勘の章・節気の横流れ）は、縦に並べた静止表示にする。
- 空もようは、自動切替と切り替えの動きだけを止め、押して切り替える操作は同じにする（両方の画面を自分で読める）。

## 文言の制約（前版から継続）

- 予報を自ら行うと受け取れる表現は避ける。ふりかえりと比較は「実績」と明記する。
- 「平年」は使わず、「5年平均」と言う。
- 料金表の有料列は「※予定」を維持する。
- 数字は撮影日の実際の値（東京）を使い、出典として「東京・2026年の実績」を添える。

## 計測

- ボタン2つのクリック、詳しく読む層の開閉（現行どおり）。
- 新しく、各章が画面に入ったことを記録する（どこまで読まれたか）。章ごとに1回だけ送る（`lp_chapter_view`）。
- 新しく、空もようの切り替えが押されたことを記録する（`lp_moyo_toggle`。触れる仕掛けが効いているか）。

## 検証

- `npm run build`・テスト・tsc が通ること。
- dev サーバーで 375px・1280px・reduced-motion をそれぞれ撮影し、全章を目視で確認する。
- スクロールの滑らかさ: スマホ相当の環境で、背景の描画が重すぎないことを確認する（CPU を絞った Playwright で計測）。
- Open-Meteo への要求が LP から出ていないことを、ネットワークログで確認する。
- ユーザーが実機で確認（develop プレビュー）→ 指示があれば main に反映する。

## 範囲外

- 写真素材の使用、動画、WebGL。
- LP 上でその場の気象データを取得すること（Open-Meteo の利用上限のため。数字は撮影時の値で固定する）。
- 途中のボタン（最初と最後の2か所にまとめる）。
