# 今年のあゆみ（一行比較）＋ 節気ふりかえりカード 設計

- 日付: 2026-10-03
- 背景: AIコメントが読まれにくい。「読ませる」より「見せる」形で、取得済みデータの価値を届ける。
- 法的前提: 気象業務法上の予報業務に当たらないよう、**過去の実績値の集計・比較のみ**を扱う。将来の見通し・推測は一切出さない。

## 段階

- **第1段階（本仕様）:** 全ユーザー向け。数値と決まった文型のみ。AI 不使用。
- **第2段階（別仕様・後日）:** 有料／AI許可ユーザー向けに、カードへ AI の短い講評を追加。

## 1. データ

| 用途 | 取得元 |
|---|---|
| 日別実績（今年・過去年） | `fetchDailyActuals(lat, lon, start, end)`（[src/api/weather.ts](../../../src/api/weather.ts)）で必要期間（約6〜7年）を**1リクエスト**で取得。※当初は年単位 `fetchWeatherData` の並列取得だったが、archive API の同時接続上限で 429 "Too many concurrent requests" になったため変更（2026-10-04 実画面検証で判明） |
| archive の直近欠け | 既存予報データの `pastDaily`（過去7日）で補完。日平均気温は (最高+最低)/2 で代用 |

- 比較年: 今年 Y、去年 Y-1、5年平均 = Y-1〜Y-5 の平均（去年を含む）。
- 節気が年をまたぐ場合（冬至・小寒など）は、必要な年を範囲から算出して取得する（例: 範囲 12/21〜1/5 の5年平均には Y-6 も要る）。
- 取得は**予報の取得完了後**に開始し、年ごとに並列で取得する。予報表示を一切待たせない。
  - 「予報の取得完了」は、予報データが**今選んでいる地点のもの**であることで判定する（予報データに取得地点の緯度経度を持たせて照合）。地点切替直後に旧地点の予報で取得を始めない。
- 当年分の実績は日々伸びるため、メモリキャッシュを **6時間で失効**させ取り直す（過去年は確定値なので無期限）。開いたまま数日使っても直近の欠けが残らないようにする。
- 取得失敗・地点なし時は機能ごと非表示（エラー表示しない）。

## 2. 一行比較「今年のあゆみ」

- 積算気温 = 1月1日からの日平均気温の合計（0℃基準の有効積算。**日平均が0℃未満の日は0として加算**し、積算値が減らないようにする）。
- 「今年」は **today の暦年**で固定する。昨日までの実績が today の年に1日も無い場合（1/1、または当年データ未着の年初）は、前年分を「今年」として数えず、直近30日の表示に切り替える。
- 今年の最新日 D までの積算値 A に対し、比較年が A に到達した日を探し、日数差を出す。
  - 正 = 早い、負 = 遅い、0 = 同じ。表示: 「積算気温 去年より4日早い・5年平均より2日早い」
  - 比較年が年末までに A に届かない場合（年末近くで今年が早い）は日数を出さず「去年より早いペース」と表示。
  - 5年平均は「1/1からの日数ごとの積算値」を5年分平均した曲線で同じ計算をする（閏年は1/1からの通し日数で揃える）。
- A < 200℃・日 の間（主に1月）は、直近30日の平均気温差に切り替える: 「直近30日の平均気温 去年より+1.2℃・5年平均より+0.4℃」
- 見出しラベル: 「今年のあゆみ（1月1日から）」／切替時は「この30日」。

## 3. 節気ふりかえりカード

- 対象: 直前に終わった節気（開始日〜終了日、JST 暦日）。開始日は既存 `sekkiForDate` で日ごとに節気番号が変わる日を探して求める。
- 内容:
  1. その節気のイラスト（既存 `SekkiArt`）と期間「白露 9/7〜9/22（16日間）」
  2. 見出しの一文（下記の文型）
  3. 3項目 × 3列: 平均気温（℃／差）・雨の量（mm／割合）・日照（h／差）を「今年／去年比／5年平均比」
     - 比較年は同じ月日範囲で集計。
     - 雨の比較基準が 5mm 未満のときは割合でなく mm 差で表示（0除算・誤解の防止）。
  4. 日ごとの雨の棒グラフ（期間の全日）
  5. 記録: いちばん暑い日（最高気温の最大）・いちばん涼しい朝（最低気温の最小）・まとまった雨（10mm以上の日の最大。無ければ「なし」）
- 見出しの文型: 5年平均とのずれを判定し、ずれの大きい順に最大2項目を組み合わせる。
  - 気温: +1℃超「暑い」／−1℃未満「涼しい」
  - 雨: 0.7倍未満「雨が少ない」／1.3倍超「雨が多い」
  - 日照: +15%超「日差しの多い」／−15%未満「日差しの少ない」
  - 該当なし: 「平年並みの穏やかな半月でした」
  - 例: 「雨が少なく、日差しの多い半月でした」
  - 「平年並み」の語は5年平均を指す慣用表現として使う（数値表示は「5年平均」と明記）。

## 4. 置き場所と表示

- 空もようタブ、ヒーロー直下（既存の重なり領域の先頭）。
- 一行比較の帯: 常設。取得中は同じ高さの骨組み表示（`Skeleton`）で場所を確保し、完了で差し替え。失敗時は骨組みごと消える。
- カード: **新しい節気の初日から3日間（初日を含む3暦日）だけ**帯の下に表示。完了時に高さを滑らかに広げて登場（Motion、reduced-motion では即時）。
- 3日間以外: ヒーローの節気名（`SekkiBadge`）をタップすると `Sheet` でカードを開く。バッジはボタン化（aria-label「白露のふりかえりを開く」）。
- 地点を切り替えたら、その地点のデータで計算し直す。

## 5. 計測（GA4）

- `season_card_view`: カード本体の半分以上が画面に入った（IntersectionObserver で検知。帯下・シートの両方で、1セッション1回。最初に見た場所を `source: inline | sheet` で記録）
- `season_card_open`: 節気名タップでシートを開いた
- 既存 `src/lib/analytics.ts` に追加。

## 6. 構成

| 単位 | 役割 |
|---|---|
| `src/lib/seasonReview.ts` | 純粋関数: 節気範囲の算出、日別データの結合（archive＋pastDaily）、積算・到達日・日数差、30日平均差、範囲集計、記録抽出、見出し文型 |
| `src/hooks/useSeasonReview.ts` | 予報完了後に必要年を取得し、上記で一行比較とカードのデータを作る。状態: loading / ready / hidden |

| `SekkiBadge` / `WeatherTab` | バッジのボタン化とシート、帯・カードの配置 |

## 7. テスト

- `seasonReview.ts` の各関数に単体テスト: 年またぎ範囲、閏年、archive 欠けの補完、到達日が見つからない場合、200℃・日しきい値の切替、雨基準5mm未満、見出しの全分岐。
- 部品: 骨組み→本体差し替え、hidden で何も描かない、3日間判定、バッジタップでシートが開く。
- 既存テスト・ビルドが通ること。バンドル増分を記録する。

## 対象外（YAGNI）

## 追補（2026-10-04）: 季節のあしどり

ユーザー確認で次のとおり変更した。

- 名称「今年のあゆみ」→「**季節のあしどり**」。
- 帯は4項目を約8秒ごとに、約0.8秒のゆっくりした縦スライドで切り替える（紙芝居）。本文の先頭に項目名（気温など）を色付きで置き、見出しは「季節のあしどり（期間）」。順は 気温 → 降水量 → 積算温度 → 日照時間。タップで次へ。動きを減らす設定では自動送りなし。画面外・背面では停止。読み上げ用に全項目の一覧をボタンの外に置く。
- 比べ方の設定（設定 → 空くらべ「季節のあしどりの比べ方」、Firestore `seasonPaceMode`、ゲストは既定）:
  - **空くらべに合わせる（既定）**: 降水量・積算温度・日照時間は空くらべの累積開始日から。積算温度は**基準温度1**（既定10℃、設定でメインと明記）で、空くらべと同じ「比較年が届いた日」との日数差。積算が日数差ガード（空くらべの設定、既定30）未満の間は同じ日数時点の差（℃日）。
  - **直近30日**: 3項目も直近30日。積算温度は30日の積算の差（℃日）。
  - 気温はどちらも直近30日の平均。開始日がまだ来ていない項目は出さない（「今年」は today の暦年で固定）。
- 旧仕様の「積算200℃日未満は30日平均に切替」は廃止（気温項目が常に30日を担うため）。

## 追補（2026-10-04 その2）: 項目ごとの比べ方と単位

- 比べ方は**項目ごと**に選ぶ（降水量・積算温度・日照時間 × 「累積（空くらべの開始日から）」／「直近30日」）。Firestore `seasonPaceModes: { precip, gdd, sunshine }`。旧 `seasonPaceMode`（全項目共通）は読み込み時に全項目へ引き継ぐ。気温は常に直近30日で、設定画面には注記のみ。
- 積算温度の単位: 直近30日は「℃」（30日の積算の差）、累積は「日」（何日早い／遅い）。℃日は使わない。累積で積算が日数差ガード未満の時期は積算温度の項目を出さない。

## 追補（2026-10-04 その3）: 過去の節気を左右スライドで

- 節気名タップのシートで、直前の節気から**6節気（約3か月）**のふりかえりを横スライドで見られる。左が古く右が最新、最新から表示。点・左右の矢印でも移動、シートの見出しは表示中の節気名。計算できない節気は並べない。
- 帯の下に3日間出すカードは最新1枚のまま。
- 年初は6節気前が前年秋になるため、必要年をその5年前まで広げる（過去年は端末保存なので追加の取得は初回のみ）。
- 計測: `season_card_browse`（何節気さかのぼったか `back`、値ごとに1セッション1回）。
